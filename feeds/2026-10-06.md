**🕒 15:47 👤 @ricardodaf@masto.es**
💬 ¡Gente del Fediverse! 👋🐧 Hoy les traigo una herramienta de infraestructura que es magia pura para las instancias pequeñas: Activity-Relay.

Ojo: no es una app para tu celu, es un servidor de retransmisión (relay) escrito en Go que conecta instancias de Mastodon, Misskey y Pleroma. 🧵👇

📬 ¿El problema? Las instancias nuevas o chicas suelen tener el "timeline local" vacío porque nadie las conoce aún.

Activity-Relay actúa como una oficina de correos central: tu instancia se "suscribe" a él, y el relay le reenvía todos los posts públicos de las demás instancias conectadas. ¡Federation boost! 🚀

🔓 Licencia: GNU AGPL v3. 100% software libre.

Su filosofía es fortalecer la red descentralizada. En lugar de depender de que los usuarios sigan cuentas una por una en otros servidores, el relay garantiza que el contenido público fluya, manteniendo viva la diversidad del Fediverse sin centralizar los datos. 🤝

💻 ¿Dispositivos? Es backend puro. Corre en servidores Linux, VPS o contenedores Docker (no es una app de escritorio/celular).

Requisito clave: Redis.
Instalación (tl;dr):
1️⃣ git clone y compilar el binario en Go.
2️⃣ Configurar config.yml.
3️⃣ Correr: relay --config config.yml server (y el worker).

🌐 Para instancias Mastodon/Misskey: solo hay que suscribirse a https://<tu-relay>/inbox. ¡Así de fácil!

Si administrás una instancia (o querés armar una en tu Raspberry Pi), esta es la pieza que le falta al rompecabezas para que no se sienta vacía.

🔗 [https://github.com/yukimochi/Activity-Relay](https://github.com/yukimochi/Activity-Relay)

¿Tu instancia usa algún relay público? ¿Conocías esta herramienta? ¡Los leo! 👇🍷

**🕒 21:05 👤 @mitchellh@hachyderm.io**
💬 I've published a new, general-purpose terminal specification that gives any program a way to tell the terminal what it's doing: idle, working, waiting, finished, or failed, and why. It is easy to implement on both sides. I've written more about why: [https://mitchellh.com/writing/program-status-osc7501](https://mitchellh.com/writing/program-status-osc7501)

The problem this solves is generic and applies in compelling ways to all sorts of use cases (e.g. package managers, build tools), but it really rears a hideous head when it comes to AI and the "agentic inbox" problem.

I found over 250 different agent orchestrators (with various goals) that all individually implement a heuristic based approach to detecting whether things like Claude Code are working, blocked, done, etc. 

If you look at Herdr’s commit history, you can see around 10 compatibility changes to detect Claude Code within just the past 3 months. (This isn't a dig at Herdr! They're doing great work with what they have, and everyone else is doing the same thing). 

Heuristics are not the way. And over-indexing on agentic use cases isn't the way, because this problem is really interesting for other tools too: Homebrew, Terraform, Cargo, etc. etc. 

Proprietary protocols and out of band APIs are not the way. They have an O(N) integration problem and require extra work to work over SSH or within local VMs/containers.

The program status specification (OSC 7501) solves this in a reliable, deterministic way that is general-purpose and can be easily adopted by the entire industry. 

Read more: [https://mitchellh.com/writing/program-status-osc7501](https://mitchellh.com/writing/program-status-osc7501)
