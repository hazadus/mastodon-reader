**🕒 15:17 👤 @itamarst@hachyderm.io**
💬 RE: [https://mastodon.social/@glyph/117596993872021290](https://mastodon.social/@glyph/117596993872021290)

A specific example: having a backend with JSON endpoints and a frontend in React involves lots of boilerplate.

But if you pay attention you'll notice that 90% of this complexity is unnecessary for 90% of websites. You can just generate HTML on the backend and sprinkle on some HTMX; no need for React for simple things.

Another specific example: microservices, copied from massive organizations that used it as a way to deal with massive-org problems. They had 5 devs per microservice. Small companies copied it and went the other way, sometimes with multiple services per dev. Distributed systems are complicated! And now you probably need something like Kubernetes, which is massive overkill for small teams because it was designed by Googlers.

I was able to build a (admittedly tiny) SaaS as a single person, with billing and a management UI and the actual product, because I avoided all this unnecessary complexity, which meant it just wasn't that much code.

**🕒 21:49 👤 @mitchellh@hachyderm.io**
💬 libghostty-vt 1.0.1 released. ABI stable so its a drop-in upgrade. Enjoy the hand-written release notes below. [https://lib.ghostty.org/](https://lib.ghostty.org/)

Highlights

- Prebuilt Windows builds. Releases now include zips for x86_64 and aarch64 (Windows on Arm), each with the DLL, import and static libraries, headers, CMake and pkg-config files.
- Faster memory operations on Linux. Builds that dynamically link glibc now use its memset, memcpy and memmove, which pick the best CPU features at runtime and beat Zig's compiler_rt in every benchmark we have.
- Fixed garbled input with an AVX-512 system.

Bug Fixes

- Resizing the column count no longer leaves stale shell prompts behind when the shell redraws its prompt (OSC 133). This was most visible with full-line prompts like powerlevel10k.
- A resize that grows rows and shrinks columns at the same time now pulls scrollback down correctly, matching what you get from doing the two resizes one after the other.
- A failed render state update no longer marks unfinished rows as clean.
- Kitty graphics: during a chunked transmission that replaces an image, the old image now stays until the transmission ends, instead of disappearing on the first chunk.

Performance

- Setting a scrollback line limit now performs the same as a byte limit. We previously decommitted memory only in the line-limit case, which caused storms of page faults. With a 1,000-line limit, ASCII throughput went from 298 to 1,983 MB/s on Linux (6.7x) and from 2,214 to 4,093 MB/s on macOS (1.8x). Matches byte limit performance.
- A restored snapshot's last page now gets its full pooled capacity, so the first write after a restore doesn't immediately allocate.
- Linux builds that dynamically link glibc now use glibc's memset, memcpy and memmove (with runtime CPU feature detection) instead of Zig compiler_rt's. ASCII with no scrollback is 23% faster on arm64 and 10% faster on x86_64. Resizing is 4–10% faster.
- UTF-8 decoding after the first invalid sequence no longer decodes valid runs twice. Valid input is unchanged, and input with invalid sequences decodes 6–10% faster.
- Faster CSI parameter parsing: 14 instructions and 2 branches per digit on x86-64, down from 23 and 5. Style-heavy streams are up to 5% faster.
